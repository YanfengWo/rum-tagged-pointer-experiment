# Brief 260 — split the kernel `namespace.rs` catalog (file-size hygiene)

## Goal

`crates/rum-runtime/src/runtime/builtin_catalog/namespace.rs` (26.0 KB,
split-plan range per AGENTS.md) is broken into three responsibility-based
sub-modules under a `namespace/` directory, each exporting one sub-const.
The kernel catalog aggregator concatenates the three exactly as it
concatenates the current single const. PURE REORGANIZATION: the set of
registered builtins, their order in the aggregated slice, their
attributes, messages, summaries, and the generated reference are all
UNCHANGED. `docs/reference/builtins.md` regenerates BYTE-IDENTICAL.

## The split (contiguous, order-preserving; cut at family boundaries)

The current `NAMESPACE_BUILTINS` array has 64 entries in this order.
Split into three contiguous runs, each a new sub-const:

- `NAMESPACE_VARIABLE_BUILTINS` — from `$Context` through `Nothing`
  (the system `$`-variables plus `Nothing`).
- `NAMESPACE_CONTEXT_BUILTINS` — from `FileNameJoin` through `Once`
  (file-name path ops, contexts/names, file access, package loading,
  save/persistence).
- `NAMESPACE_SYMBOL_BUILTINS` — from `Message` through `Quiet`
  (message machinery, definitions/values, attributes/options,
  protection, `Check`/`Quiet`).

Keep every entry verbatim and in its current relative order within its
run. Do not edit any entry's text, attributes, or messages.

## Mechanism (director-verified sites, 2026-07-18)

The aggregator is a runtime `Vec` built by `extend_from_slice`, so
adding sub-consts is clean — no const concatenation needed.

- Convert the file to a directory module:
  - `builtin_catalog/namespace/mod.rs` — `mod variables; mod contexts;
    mod symbols;` and `pub(super) use` re-exports of the three
    sub-consts (so the paths `namespace::NAMESPACE_VARIABLE_BUILTINS`
    etc. resolve). Delete the old single-file `namespace.rs`.
  - `builtin_catalog/namespace/variables.rs`,
    `.../contexts.rs`, `.../symbols.rs` — each `use super::*;` (the
    old file's imports still resolve at this depth because `mod.rs`'s
    `use super::*;` re-exports the parent's glob; VERIFY the imports
    compile — if a `use` needs `super::super::`, fix it minimally and
    note it). Each holds one `pub(super) const NAMESPACE_*_BUILTINS:
    &[BuiltinSpec] = &[ … ];`.
- `builtin_catalog.rs` (the aggregator):
  - `mod namespace;` stays (now resolves to `namespace/mod.rs`).
  - In `core_builtin_specs`: replace the single
    `+ namespace::NAMESPACE_BUILTINS.len()` capacity term with the
    three sub-const `.len()` terms, and replace the single
    `specs.extend_from_slice(namespace::NAMESPACE_BUILTINS);` with three
    `extend_from_slice` calls IN THE SAME ORDER (variables, contexts,
    symbols) so the concatenated sequence is identical.
  - These are the ONLY two consumer sites of `NAMESPACE_BUILTINS`
    (director-verified: `grep -rn NAMESPACE_BUILTINS crates` shows only
    `builtin_catalog.rs:46` and `:56`).
