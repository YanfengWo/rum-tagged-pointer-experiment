# Contributing to rum

Thanks for your interest. `rum` is an independent, personal open-source project
(see [DISCLAIMER.md](./DISCLAIMER.md)); it is developed in the open, and
contributions are welcome under the terms below.

## Before you start

Read [`AGENTS.md`](./AGENTS.md) — the operational first-stop: project snapshot,
build/test commands, and the testing policy — and [`ARCHITECTURE.md`](./ARCHITECTURE.md)
for boundaries and design commitments. Deeper context lives under [`docs/`](./docs/).

## Testing policy — permanent, non-negotiable

This is the one hard line a contribution must never cross:

1. Tests verify **`rum`'s own documented behavior** — the language guide
   (`docs/guide/`), the generated builtin reference (`docs/reference/builtins.md`),
   and the host crates' rustdoc are the normative contract.
2. **No black-box differential testing against other vendors' engines.** Do not
   add oracle harnesses, comparison lanes, compatibility matrices, or
   conformance reports — in code, scripts, fixtures, docs, or CI — and do not
   commit outputs generated by third-party engines. This policy is permanent;
   its history is recorded in [`DISCLAIMER.md`](./DISCLAIMER.md).
3. Do not "fix" a failing test by weakening its documented contract; surface the
   conflict instead.

Performance changes are gated by **`rum`-vs-`rum` A/B**
(`scripts/core-language-microbench.sh`), never against another engine.

## Development

- Toolchain: Rust `1.85` (edition 2024), the public MSRV.
- Before sending a change, both of these must be clean:

  ```
  cargo fmt --check
  cargo test --workspace
  ```

- **Safe Rust is a hard convention.** `rum-core` and `rum-runtime` are
  zero-`unsafe`; do not introduce `unsafe` into the kernel crates. If you think
  it is unavoidable, stop and raise it first.
- **Hot-path changes are measured, not asserted.** A change to eval/dispatch/the
  matcher, or to `Expr`/`SharedExpr`/`SharedArgs` construction, must be gated
  with a microbench A/B. There is no default-path cost for diagnostics.
- **Keep files within the size thresholds** in
  [`docs/code-organization-guidelines.md`](./docs/code-organization-guidelines.md)
  (split by responsibility, not arbitrarily).
- When you change documented behavior or the builtin surface, update the docs in
  the same change and regenerate the reference
  (`cargo run -p rum-stdlib --bin generate-builtin-reference`); the drift test
  enforces this.

## Submitting

- Keep changes small and reviewable; a commit message states the semantic or
  organizational change it makes.
- By contributing, you agree that your contributions are licensed under the
  project's MIT license (see [`LICENSE`](./LICENSE)).
- Be respectful; see [`CODE_OF_CONDUCT.md`](./CODE_OF_CONDUCT.md).
