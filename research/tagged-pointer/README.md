# rum 原版基线与标签表示实验入口

## 有界符号载荷共享

新增同一策略的 Safe/Compact 符号共享对照，独立头部和参数身份保持不变。真实 Association 的紧凑版保留堆比归一化原版少约 26%，但不同符号和小规则的构造存在回退。原型维持可选状态，尚未迁入求值器。详见 [语义论证、完整内存与计时结果](symbol-sharing/README.md)。

## 实际测试表达式分布

新增 112 个性能测试输入与 15 个求值结果的表达式快照、共享与实际分配核对。整数列表节省明显，但符号列表增大约 75%，整数 Association 几乎不省；当前布局的收益取决于能直接编码的整数比例。详见 [语料、成本模型与下一步选择](expression-census/README.md)。这些是静态快照，不是求值器动态分配或速度结果。

## 递归表示与共享验证

已建立递归 Compact 与相同共享策略的 safe 对照，验证转换、共享、COW、Weak 和深层显式释放。实际分配测量显示：整数列表与共享子树节省保留字节，字符串和深链可能增加内存；遍历与释放也存在回退。目前不适合全面替换 Expr。详见 [递归原型、语义论证与完整测量](recursive-expr/README.md)。求值器尚未改造。

## 第二版与混合场景诊断

已简化堆指针编码并补齐类型化借用视图。通过旧版、只补内联的版本、safe 对照及原 Expr 的三轮交错测量，定位了函数调用、指针恢复和代码生成的影响。混合遍历较旧版改善，部分场景对 safe 对照仍有小幅回退。详见 [完整诊断与对照结果](representation-study/README.md)。运行时仍未改造。

## 最新外部表示原型

已实现并验证独立的 CompactExpr 原型，测得 8 字节表示，并保留 16 字节 safe 对照。整数与混合场景的计时显示收益和回退并存；尚未迁入解释器。详见 [原型、测试与计时结果](compact-expr/README.md) 和 [语义论证](compact-expr/SEMANTICS.md)。下文保存实施前的原版基线记录。

日期：2026-10-10。已完成固定版本、原版验证、布局测量、重复计时和独立分配统计。基线阶段只新增研究资料与外部布局探测，rum 运行时源码保持原样。

## 实际类型布局

| 类型 | 字节数 | 对齐 |
|---|---:|---:|
| IntValue | 16 | 8 |
| Symbol | 24 | 8 |
| Atom | 32 | 8 |
| Expr | 32 | 8 |
| SharedExpr / SharedArgs / WeakSharedArgs | 各 8 | 各 8 |
| Option&lt;SharedExpr&gt; / Option&lt;SharedArgs&gt; | 各 8 | 各 8 |
| Vec&lt;Expr&gt; 本身 | 24 | 8 |

布局探测是独立 Cargo 包，通过路径依赖使用未修改的 rum-core。其锁文件由上游锁文件起步，保留所需依赖版本。结果是该固定 Rust/target 下的实测，不是跨版本布局保证。

SharedExpr 和 SharedArgs 已占一个机器字，给它们附加标签不会进一步缩小这个字段。值得研究的是 Expr 的 32 字节元素槽位：若新的 CompactExpr 做到 8 字节，10 万个元素的槽位从 3,200,000 字节变为 800,000 字节，理论减少 75%。这不包含 Vec 预留容量、共享对象、引用计数及新增堆分配，不能解释成整个进程节省 75% 或快 4 倍。

以下是独立 alloc-count 构建的原始统计，范围为统计启用后整个新进程的分配请求，包含解析、求值及输出；不是每个表达式的次数。realloc 的增长事件也计入计数。

| 工作负载 | 分配计数 | 累计请求字节 | 统计峰值存活字节 |
|---|---:|---:|---:|
| 空基准 | 6974 | 511758 | 269643 |
| 保留 Range[1000] | 7048 | 550717 | 305240 |
| 保留 Range[10000] | 7048 | 838740 | 593252 |
| 保留 Range[100000] | 7048 | 3718765 | 3473266 |
| Module 20000 次 | 1287126 | 68107713 | 3182252 |
| 瞬时 200000 元素工作负载 | 208517 | 29352547 | 16278435 |

Range 三种规模的请求次数相同、请求字节随元素数增长，是优先研究元素槽位压缩的证据；尚不能从这些计数归因所有成本。Module 路径的请求数量较大，但仅靠压缩句柄不保证减少这些请求，需要结合共享/构造计数继续定位。

上游 MemoryInUse/MaxMemoryUsed 是模型代理值；分配统计是分配器请求值，两者都不是实际 RSS。本轮使用内存脚本的 --no-rss，因为它的 RSS 路径依赖 macOS time -l；没有把该代理或统计峰值标成 Linux RSS。

## 选择的改造方向

第一候选是 **Expr 级单字句柄：小整数立即数，加类型受控的堆对象句柄**。先在外部封装 crate 建立原型与相同堆策略的 safe 枚举对照，再迁移 rum 的调用接口；通过对照把标签压缩收益与共享策略或额外堆分配的变化区分开。

关键约束：

- 3 个低位标签使有符号立即整数剩余 61 位，范围为 `[-2^60, 2^60-1]`。其余 i64 和任意精度整数必须有无损回退，保留当前整数语义。
- 标签必须与实际载荷类型对应，编码、恢复、clone 和 drop 使用正确来源、类型及布局。现有固定 u64、8/8 布局的释放桥不能用于这些异构对象。
- 保留 Arc 共享、WeakSharedArgs、写时复制、身份比较、序列化及 HostSession 的 Send 契约；初始原型的独占拥有权、非 Send 范围不能直接套用。
- rum-core/rum-runtime 继续通过 safe API 使用封装。新增 unsafe 应局限于独立封装 crate，并明确其新的可信基础与证明义务。
- 本次文本统计在 265 个 Rust 文件发现 1441 处 Expr::Atom/Call 命中，包含测试，且不包含所有 Self:: 写法。这是迁移规模的提示，不是精确改动行数。需要先设计借用视图和构造接口。

候选准入应依次检查无损表示与行为契约、clone/drop/弱引用/COW、Miri、完整 workspace 回归、逐标签交错 A/B、分配统计和真实内存。现有 49 项 u64 联合检查只证明原受限对象，与 rum 的共享异构值之间还需新的语义关系。

本地研究入口为 experiments/rum-tagged/scripts/baseline.sh，使用已安装的固定工具链缓存。独立技术仓库中的测量入口位于 research/tagged-pointer/：
